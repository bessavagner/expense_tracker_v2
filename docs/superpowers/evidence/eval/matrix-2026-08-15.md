## The decision

### Vision: ship the pipeline

| Gate | Required | Measured | |
|---|---|---|---|
| Cost | ≤ $0.1177 per sweep (baseline ÷ 3) | **$0.0942 — 3.75×** | ✅ |
| Score | ≥ 0.631 (baseline mean − spread) | **0.719** | ✅ |
| `money_ok_rate` | ≥ 0.711 (no drop at all) | **0.756** | ✅ |
| Escalation rate | materially below 100% | **33%** (27 / 33 / 40) | ✅ |

It is not merely cheaper within tolerance. **It scores higher than the model it
replaces on both quality axes** — 0.719 against 0.699, and 0.756 against 0.711
on the invariant that governs whether the ledger is right — at 3.75× less money.

That is not a fluke of averaging. It is what the escalating pipeline is for:
`gpt-5.6-luna` reads every receipt for $0.0496, and the third it cannot
reconcile go to `gpt-5.4-mini`, which is itself the equal of `gpt-5.4` on the
money invariant. Neither model alone clears the bar — luna fails quality by a
mile, mini misses the cost gate at 2.48× — and the composition of the two clears
all four gates. **S09-3 is exactly right that the pipeline's score is what
ships.**

At 33% escalation the mix pays for roughly 1.33 calls per receipt. That is the
number to watch: see *Is escalation working?* in `docs/runbook.md`.

### Text: keep `gpt-5.4`, and say why

Both candidates are cheaper — luna by **9.67×** — and both score 0.952 against
the baseline's 1.000. They fail the same case, `americanas-split-on-request`,
one run in three.

That case is not incidental. It is the transcript of the production bug this
product exists to prevent: asked to split a receipt by category, the agent
booked `Roupa R$42,16` and `Lanche R$0,00`. gpt-5.4 passes it 3/3 with a spread
of 0.000; both candidates reintroduce a one-in-three chance of it. Saving
$0.28 a sweep is not worth that, and the behavioural gate — set before the
candidates ran — says 1.000.

Recorded for E10: **on text, luna is as good as mini and 3.4× cheaper again.**
If the ESSENTIAL tier ever needs a better degraded model than the free
OpenRouter one, luna is the measured answer, and the only case it costs is one
this dataset can already name.

### Rejected outright: `openai-responses:gpt-5.6-terra`

1.63× **dearer** than the baseline and worse on every quality column. It
consumes 201,582 input tokens where gpt-5.4 uses 74,881 for the same fifteen
images, so a 20%-lower list price still bills more.

This is the second independent measurement to say so: E08 measured the same
family at 51% more expensive per receipt on a different suite, and commit
`63d9743` had already moved production onto it on the strength of its list
price alone. **Two sweeps, two datasets, the same answer — list price does not
predict cost here; token consumption does.**

## What the matrix changed about the code

The first pipeline sweep failed the money gate at 0.689 while escalating only
**22%** of the time — on a cheap model that fails the invariant on nearly half
the set. Both numbers could not be right.

`should_escalate` asked `receipt_is_consistent`, which deliberately does not
subtract the discount and must not: it exists to catch a line the model failed
to read, and subtracting an already-embedded discount raised false alarms on
receipts printing a net `Valor Liquido`. That makes it one-sided, and blind to
the failure that dominates this dataset — an already-net line total reported
next to the receipt's printed discount:

```
items                   40.00
items - discount        20.00   <- what the ledger would record
amount_paid             40.00
receipt_is_consistent   True    <- happy: items alone cover the total
should_escalate         None    <- keeps a read that posts R$20 for a R$40 purchase
```

What reaches the ledger is `items − discount`, so that is what must land on the
amount paid. With that fixed, escalation rose 22% → 33% and the same mix went
from failing the money gate to beating the baseline on it:

| | Escalation | Score | `money_ok` | USD | Factor |
|---|---|---|---|---|---|
| Rule v1 (`receipt_is_consistent` only) | 22% | 0.651 | 0.689 ❌ | $0.0823 | 4.29× |
| **Rule v2 (ledger figure must reconcile)** | **33%** | **0.719** | **0.756** ✅ | $0.0942 | **3.75×** |

The gates did not move. A component E09 introduced was wrong, the measurement
proved it, and the fix cost 14% of the saving.

## Reproducing

```bash
for i in 1 2 3; do
  RUN_LLM_TESTS=1 POSTGRES_PORT=5433 EVAL_FIXTURES_DIR=~/ledger-eval-fixtures \
  uv run python src/backend/manage.py eval_models \
    --pipeline "openai:gpt-5.6-luna,openai:gpt-5.4-mini" --suite extraction \
    --out docs/superpowers/evidence/eval/matrix-pipeline-v2-lunamini-$i.md
done
```

Every candidate was smoke-tested on a single case before any sweep. None of
these four refused tool calling, so `assistant/agents/model_compat.py` needed no
new entry — but two of the three models first pointed at this dataset during E08
returned HTTP 400 on every call, and a full sweep against a model that cannot
answer buys a table of zeroes.

The whole matrix, including the re-run, cost about **$11**.
